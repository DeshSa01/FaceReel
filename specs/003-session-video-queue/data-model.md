# Data Model: Session Video Queue

Every durable record lives under `storage/sessions/<sid>/` (research D1). Runtime-only fields are marked **(memory)**. They are never written to disk and are rebuilt as empty on start-up.

## Identifiers

| Id | Format | Generated by | Uniqueness |
|---|---|---|---|
| Session id `sid` | `^[0-9a-f]{12}$` | `uuid4().hex[:12]` | Re-rolled if `storage/sessions/<sid>` **or** `storage/archive/<sid>` exists (research D6) |
| Video id `vid` | `^[0-9a-f]{12}$` | `uuid4().hex[:12]` | Re-rolled if it collides with any session's video, or with an archive entry. It becomes the video's archive entry id |
| `seq` | positive int | global counter: `max(seq on disk) + 1` at start-up, incremented per add | Unique across all sessions. Orders videos *within* a session; the line orders by `(session created_at, session id, seq)` (research D2) |

Every id received in a URL or form field is validated with `archive.valid_id` **before** it is used to build a path (FR-023, Constitution Principle V).

## Session

`storage/sessions/<sid>/session.json`

| Field | Type | Notes |
|---|---|---|
| `id` | str | `sid` |
| `created_at` | ISO-8601 str, with UTC offset | Same format as archive sidecars |
| `state` | enum | See transitions below |
| `videos` | list[Video] | In order added; never reordered; removed videos stay in the list |
| `completed_at` | str \| null | Set when the session leaves `open` |
| `result` | object \| null | Set when the session ends. On `finished`: `{archive_id, output_duration, resolution, clip_count, joined_count, videos}`. On `nothing_to_join` / `join_failed`: `{joined_count: 0, videos}`. `videos` is the per-video summary `[{vid, title, url, state: joined\|skipped\|failed, reason?}]`, the same list written to the archive sidecar |
| `error` | str \| null | Set on `join_failed` |

**Derived (returned by the API, not stored)**: `counts` by video state; `title`, the first video's title once known; `first_url`, its link, which the chooser shows until the title is known; `prefill`, taken from the last non-removed video: `{from_video, tuning}` (research D7).

### Session state transitions

```text
                add_video (≥1 video)                 last video done/failed/removed,
   ┌────────┐ ───────────────────────►  ┌────────┐  none waiting or processing   ┌─────────┐
   │  open  │                           │  open  │ ───────────────────────────► │ joining │
   └────────┘ ◄─ (empty: may be         └────────┘   (_maybe_complete, D4)       └────┬────┘
       │          discarded, FR-024)                                                  │
       ▼                                                    ┌─────────────────────────┼──────────────────────┐
   (deleted)                                                ▼                         ▼                      ▼
                                                      ┌──────────┐          ┌─────────────────┐     ┌─────────────┐
                                                      │ finished │          │ nothing_to_join │     │ join_failed │
                                                      └──────────┘          └─────────────────┘     └─────────────┘
```

- `open` → `joining`: the session has ≥1 video and no video is `waiting` or `processing`. This is the only automatic transition (FR-011).
- `joining` → `nothing_to_join`: no `done` video has a reel still in the archive (US2 scenario 4).
- `joining` → `finished`: `archive.archive_session` succeeded.
- `joining` → `join_failed`: ffmpeg or the archive step raised an error. Individual reels are untouched (FR-022).
- Ended states are left only by a retry (FR-025): `finished` / `nothing_to_join` / `join_failed` → `open`, with failed videos → `waiting`, and `completed_at`, `result` and `error` cleared. Videos can only be added in `open`.
- **Restart** (research D3): `joining` stays `joining` and the join is retried, unless `storage/archive/<sid>` holds a reel created **at or after** this `completed_at`, in which case it becomes `finished`. An older reel there is the one a retry is replacing, and must not be mistaken for the result.

## Video

An element of `Session.videos`.

| Field | Type | Notes |
|---|---|---|
| `id` | str | `vid`; the archive entry id once done |
| `seq` | int | Position in the application-wide line |
| `index` | int | 1-based order of addition, stored and never renumbered. Display uses `display_index` (below) |
| `url` | str | Source link |
| `screenshot` | str | Filename under `storage/sessions/<sid>/screenshots/` (`<vid>.<ext>`) |
| `tuning` | object | `asdict(pipeline.Tuning)`, clamped at add time exactly as today |
| `state` | enum | `waiting` \| `processing` \| `done` \| `failed` \| `removed` |
| `added_at` | str | ISO-8601 |
| `finished_at` | str \| null | Set on `done`/`failed` |
| `title` | str \| null | From the pipeline result |
| `result` | object \| null | On `done`: `{clip_count, output_duration, source_duration, resolution, zoomed_clips, filename}` |
| `error` | str \| null | On `failed`: the `PipelineError` text, or "Unexpected error: …" |
| `stage`, `progress`, `message` | **(memory)** | Only while `processing`; same vocabulary as today's job record |

**Derived**: `display_index` is the 1-based rank among this session's non-removed videos. It pairs with the session's `total`, which also excludes removed videos, so a display never reads "video 6 of 5". `line_position` for a `waiting` video = 1 + everything ahead of it in queue order (waiting videos of older sessions, earlier videos of its own session) + whatever is processing + pending joins. `ahead_own` / `ahead_other` split that count by session, so the page can say when the wait is for another session.

### Video state transitions

```text
 waiting ──runner picks first in queue order──► processing ──pipeline+archive ok──► done
    │                                     │
    │ DELETE (FR-012)                     └──PipelineError / exception──► failed
    ▼
 removed                     restart: processing ─► waiting (same seq), or done if archive/<vid> exists (D3)
```

- `processing` cannot be removed (FR-013).
- Being interrupted by a restart never produces `failed` (FR-020).

## Limits and validation

| Rule | Where | Error |
|---|---|---|
| ≤ 10 non-`removed` videos per session (`MAX_VIDEOS_PER_SESSION`) | `add_video`, under the lock | 409 `"A session holds at most 10 videos."` |
| Add only while `open` | `add_video`, under the lock | 409 `"This session has completed. Start a new session to add more videos."` |
| Exactly one of `screenshot` / `screenshot_from` | `add_video` | 400 |
| `screenshot_from` names a video in the **same** session | `add_video` | 400 |
| Remove only `waiting` | `remove_video` | 409 |
| Discard only a session with zero videos | `discard_session` | 409 |
| Malformed `sid`/`vid` | every route | 400 (as the archive routes do today) |
| Unknown `sid`/`vid` | every route | 404 |

## Archive sidecar extension (`storage/archive/<id>/reel.json`)

New optional fields. A sidecar without them is a single-video reel, so existing archives need no migration (research D6).

| Field | Type | Present on |
|---|---|---|
| `kind` | `"video"` \| `"session"` | Every new entry. Absent means `"video"` |
| `session_id` | str | Single-video reels made inside a session |
| `videos` | list[{`vid`, `title`, `url`, `state`, `reason`?}] | Session reels, in session order, including skipped/failed ones (US2 scenario 3) |

Session reels set `url` to `null`. `title` becomes `"Session <sid> · N videos"`, `filename` becomes `facereel-session-<sid>.mp4`, and `clip_count` is the sum over the joined videos. `screenshot` is `null`.

## On-disk layout

```text
storage/
├── jobs/                    # scratch, wiped at start-up (unchanged)
│   ├── <vid>/               #   one per processing video
│   └── join-<sid>/          #   one per running join
├── sessions/                # NEW — durable session store
│   └── <sid>/
│       ├── session.json
│       ├── session.json.tmp #   transient; only during an atomic write
│       └── screenshots/
│           └── <vid>.<ext>
└── archive/                 # unchanged layout; gains session entries
    ├── <vid>/               #   single-video reel (kind: video, session_id)
    └── <sid>/               #   joined reel (kind: session)
```
